# 为什么只使用一个 AI 工具，也值得使用 AMH

AMH 不是某个模型或 Agent 的升级版，也不要求同时接入多个工具。它首先是一个本地、可审计的协作记忆与任务控制层：工具可以只有一个，AMH 仍然负责把上下文、任务、证据和恢复点留在可复用的位置。

## 单工具用户得到什么

- **上下文不丢失**：每次任务的目标、约束、过程记录和验证结果进入共享记忆，下一次会话可以继续，而不是重新解释背景。
- **任务有状态**：任务从待处理、进行中、待验证到完成有明确生命周期，完成结果、失败原因和下一步都可追踪。
- **Checkpoint 可恢复**：在长任务中保存阶段性快照；窗口关闭、模型切换或执行中断后，可以从最近检查点恢复。
- **结果可验证**：命令输出、测试结果、审查意见和人工批准都形成证据链，避免“看起来完成”被当成已完成。
- **经验可复用**：任务完成后可提取候选技能；只有经过审核的候选才能晋升为规则或技能，避免把偶然回答写成永久知识。
- **未来可扩展**：今天只用 Codex、Claude 或 Gemini 中的一个，明天仍可按任务把部分工作交给另一个工具；历史上下文和任务状态不绑定单一 Agent。

## AMH 的最小使用方式

```text
提出任务 → 记录任务与约束 → 执行 → 保存 checkpoint → 验证/审查 → 完成并沉淀经验
```

这条闭环即使只有一个执行工具也成立。多 Agent 协作是在同一条闭环上增加角色和并行执行，不是使用 AMH 的前提。

## 适合单工具用户的判断标准

如果任务会跨多个会话、需要反复验证、包含较多约束，或者未来可能交给其他人/工具继续，那么 AMH 的价值已经存在。只有一次性、无需恢复、无需审计的极短操作，才可能不需要完整的 AMH 闭环。
